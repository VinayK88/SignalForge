## Platform overview

SignalForge models the full lifecycle of an adversarial business decision rather than a standalone fraud classifier:

```text
Account / Device / Payment / Order / Fulfillment events
                         │
                         ▼
                 Feature engineering
                         │
       ┌─────────────────┼──────────────────┐
       ▼                 ▼                  ▼
 Calibrated fraud   Isolation Forest   Graph-derived risk
 probability          anomaly score       + ring signals
       │                 │                  │
       └─────────────────┼──────────────────┘
                         ▼
                Expected-loss model
                         │
                         ▼
               Cost-sensitive policy
                         │
              ALLOW / REVIEW / BLOCK
                         │
       ┌─────────────────┴──────────────────┐
       ▼                                    ▼
 Analyst disposition                  Business outcome
       │                                    │
       └─────────────────┬──────────────────┘
                         ▼
             Active learning + drift
```

The project is intentionally designed around three questions:

1. **What is the probability that this event is fraudulent or abusive?**
2. **What is the expected business loss if the event is allowed?**
3. **Which action minimizes total expected cost while controlling customer friction and review load?**

## Machine learning stack

| Layer | Technique | Purpose |
| --- | --- | --- |
| Fraud classifier | Gradient Boosting + probability calibration | Estimate calibrated fraud probability |
| Expected loss | Gradient Boosting Regressor | Estimate conditional financial exposure |
| Behavioral anomaly | Isolation Forest | Surface novel / low-frequency behavior |
| Graph risk | Shared-entity graph features | Capture device, payment, address and account-ring structure |
| Cohort discovery | DBSCAN | Surface emerging behavioral clusters |
| Active learning | Uncertainty + disagreement ranking | Prioritize analyst labels with highest information value |
| Drift monitoring | PSI + outcome/calibration movement | Detect population and adversarial behavior change |
| Decision engine | Expected-cost optimization | Convert model evidence into ALLOW / REVIEW / BLOCK |

All public model evaluation uses deterministic synthetic populations generated by the repository. Results are regression evidence for the codebase, not production fraud-performance claims.

## Cost-sensitive decisioning

SignalForge does not assume that the highest fraud score should always be blocked.

```text
Expected action cost =
    residual fraud loss
  + false-positive customer friction
  + manual-review cost
  + fulfillment intervention cost
```

For every event the engine compares the modeled cost of each action:

```text
ALLOW   $41.20
REVIEW  $12.45   ← selected
BLOCK   $28.00
```

This separates **prediction** from **business decision policy** and makes the tradeoff auditable.

## Adversarial monitoring

SignalForge monitors both model health and the behavior of the underlying population:

- feature PSI for velocity, account age, device sharing and refund behavior;
- prediction-distribution drift;
- calibrated probability vs observed outcome movement;
- emerging DBSCAN cohorts;
- disagreement between supervised and anomaly signals;
- false-positive / review-rate movement;
- active-learning queue concentration.

A useful distinction is preserved in the report:

```text
population drift ≠ concept drift ≠ adversarial adaptation
```

The monitor surfaces evidence for analyst investigation; it does not automatically retrain or change production policy.

## Batch & SQL

The repository includes:

- deterministic synthetic generation so the project can run without external data.

## Evaluation boundary

Everything in this repository is **synthetic and defensive**. SignalForge does not claim Apple, financial-institution, retailer, customer, payment-network or production fraud metrics. Synthetic loss values and decision costs exist only to exercise the decision-science architecture.
