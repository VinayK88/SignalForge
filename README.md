## Platform overview

SignalForge models the full lifecycle of an adversarial business decision rather than a standalone fraud classifier:

```text
Account / Device / Payment / Order / Fulfillment events
                         │
                         ▼
                 Feature engineering
                         │
       ┌─────────────────┼──────────────────┐
       ▼                 ▼                  ▼
 Calibrated fraud   Isolation Forest   Graph-risk model
 probability          anomaly score      + ring signals
       │                 │                  │
       └─────────────────┼──────────────────┘
                         ▼
                Expected-loss model
                         │
                         ▼
               Cost-sensitive policy
                         │
              ALLOW / REVIEW / BLOCK
                         │
       ┌─────────────────┴──────────────────┐
       ▼                                    ▼
 Analyst disposition                  Business outcome
       │                                    │
       └─────────────────┬──────────────────┘
                         ▼
             Active learning + drift
```

The project is intentionally designed around three questions:

1. **What is the calibrated probability that this event is fraudulent or abusive?**
2. **What is the expected business loss if the event is allowed?**
3. **Which action minimizes total modeled cost while controlling customer friction and review load?**

## Machine learning stack

| Layer | Technique | Purpose |
| --- | --- | --- |
| Fraud classifier | Gradient Boosting + sigmoid probability calibration | Estimate calibrated fraud probability |
| Expected loss | Gradient Boosting Regressor | Estimate synthetic financial exposure |
| Behavioral anomaly | Isolation Forest | Surface novel / low-frequency behavior |
| Graph risk | Logistic Regression over shared-entity graph features | Capture device, payment, address and account-ring structure |
| Cohort discovery | DBSCAN | Surface emerging behavioral cohorts |
| Active learning | Uncertainty + cross-model disagreement | Prioritize analyst labels with highest information value |
| Drift monitoring | Population Stability Index (PSI) | Detect feature-distribution movement |
| Decision engine | Expected-cost optimization | Convert model evidence into ALLOW / REVIEW / BLOCK |

The graph layer uses features such as shared-device account count, shared-payment account count, shared-shipping count, graph component size and risky-neighbor ratio. The public repository does not claim a GNN or production graph-learning system.

All public model evaluation uses deterministic synthetic populations generated by the repository. Results are regression evidence for the codebase, not production fraud-performance claims.

## Cost-sensitive decisioning

SignalForge does not assume that the highest fraud score should always be blocked.

```text
Expected action cost =
    residual fraud loss
  + false-positive customer friction
  + manual-review cost
  + fulfillment intervention cost
```

For each event, the engine calculates synthetic costs for `ALLOW`, `REVIEW`, and `BLOCK` and chooses the minimum-cost action. The complete cost vector and decision margin remain in the response so the business tradeoff is inspectable.

This deliberately separates **prediction** from **decision policy**.

## Adversarial monitoring

SignalForge monitors the behavior of the underlying population and separates that evidence from conclusions about attacker adaptation:

- PSI for account age, velocity, device sharing, payment sharing, shipping sharing and refund behavior;
- supervised-vs-anomaly-vs-graph disagreement;
- emerging DBSCAN cohorts;
- active-learning queue concentration;
- model evaluation metadata and feature-schema versioning.

```text
population drift ≠ concept drift ≠ adversarial adaptation
```

PSI by itself only establishes population movement. Production conclusions about concept drift or adversarial adaptation would require outcomes, calibration movement, analyst feedback and business context.

## Evaluation boundary

Everything in this repository is **synthetic and defensive**. SignalForge does not claim Apple, financial-institution, retailer, customer, payment-network or production fraud metrics. Synthetic loss values and decision costs exist only to exercise the ML and decision-science architecture.

## Engineering boundaries

- Predictive models do **not** directly execute a production action.
- Calibration, expected loss and decision cost are separate concepts in the code.
- Anomaly percentile is not a fraud probability.
- Graph-risk probability describes the synthetic ring label, not actor attribution.
- PSI is not automatically interpreted as adversarial intent.
- All decision costs are synthetic examples and remain outside the learned models.
